# macOS 版设计/实现评审与优化记录（v1.2）

对 `macos/` 全部源码做了一轮系统性审查（设计、实现、问题三个层面），修复 8 个问题、
落地 3 项性能优化（附基准实测）、按「直击本源」哲学扩展了 2 项能力。
方法：静态审查定位机制 → 无头基准脚本实测验证 → 40 项逻辑回归全过。

## 一、修复的问题

| # | 问题 | 机制与修法 |
|---|---|---|
| P1 | 地理编码失败也写缓存、且不可重试 | 网络抖动一次，失败文案永久占住该 100m 网格（原作同病）。改为只缓存成功结果；失败不置 `gpsFetched`，重开信息栏即重试 |
| P2 | 损坏文件反复重试解码 | 缩略图生成失败的文件每次进目录都重做全套解码（损坏视频要做两次抽帧尝试）。`ThumbnailCache` 增加负缓存，失败记一次、跨目录不再重做 |
| P3 | 占位符号浅色外观下不可见 | SF Symbol 模板图默认 tint 跟随 labelColor，浅色系统外观下≈黑色画在深灰网格上。固定浅灰 tint |
| P4 | 拖进度条卡顿 | 原来每次 mouse-move 都零容差精确 seek。改为拖拽中默认容差（就近关键帧），松手一次精确定位 |
| P5 | 隐藏目录当文件夹显示 | `.git`/`.Trash` 等会出现在网格里（子目录导航引入的回归）。扫描时跳过 `.` 开头目录 |
| P6 | verify.sh 硬编码 arm64 | Intel Mac 上直接编译失败。改用 `uname -m`，与 build-app.sh 一致 |
| P7 | 网格选中态不可见 | `isSelectable` 但 item 不渲染选中效果。补系统强调色描边 + 淡填充 |
| P8 | 极小窗口负高度布局 | 信息面板高度 `rc.height - 180` 无下限。加 `max(0, …)` |

## 二、性能优化（附实测）

基准环境：Apple Silicon（10 核），样本 = 12 个 H.264 视频 + 12 张 1080p JPEG + 1 张 8000×6000 JPEG。
基准脚本纯命令行运行，直接调用 App 同款函数与并发公式。

### O1 缩略图并行生成 —— 实测 7.4×

原实现单线程串行。视频抽帧单个上百毫秒，几百个文件按分钟等。
改为有界并发（`max(2, min(6, 核数-2))`）+ 会话号取消 + 完成即回填：

```
串行:    0.31s (24/24 成功)
并发×6:  0.04s (24/24 成功)   → 7.4×
```

样本是极小的合成视频；真实相机视频单个抽帧更慢，墙钟收益更大。

### O2 查看器大图解码封顶 —— 内存 3.8×（诚实记录：解码本身反而略慢）

显示是 fit-to-window、无缩放功能，故按所有屏幕最大像素维度封顶解码，屏幕显示零画质损失。
实测 8000×6000 JPEG：

```
全分辨率: 解码 146ms → 183MB 位图，单帧绘制 7.9ms
4096封顶: 解码 273ms →  48MB 位图，单帧绘制 6.8ms
```

初始假设「解码也会更快」被数据否定（ImageIO 缩放解码有重采样开销，反而 +130ms）；
绘制提速也只有 1.2×。**保留该优化的真实理由是内存**：3.8×（亿像素照片约 8×），
并且它让带 512MB 成本上限的全图缓存（O3）真正装得下多张图——不封顶时一张全景图就能挤掉整个缓存。

### O3 全图缓存 + 相邻预取 —— 来回切图零解码

- `NSCache`（count 6 / cost 512MB，按像素字节计成本，内存压力自动驱逐）
- 加载第 N 张时后台预取 N±1（仅图片；utility QoS）
- in-flight 去重：预取与前台不重复解码同一文件
- 缓存命中也自增会话号，作废在途旧解码，防止旧图迟到覆盖

按 ←/→ 时下一张大概率已在缓存，秒开；配合 O2 的封顶，6 张缓存的实际内存有界。

## 三、能力扩展（与「直击本源」哲学一致）

- **魔数嗅探扩展**：GIF、TIFF（II/MM）、WebP、BMP、AVIF → 图片管线（ImageIO 全部原生解码）。
  BMP 两字节魔数太弱，额外校验偏移 6..9 保留字段必须为 0 压误报；
  ISO-BMFF brand 增加 `hevc/heif/avif/avis`。
- **键盘导航**：网格内回车/Enter 打开选中项，Cmd+↑ 返回上级（Finder 习惯）；
  方向键选格子是 NSCollectionView 自带。

## 四、评审后决定不动的（及理由）

- **不迁 Swift Concurrency**：现有「会话号 + GCD」取消模式经审查无竞态，迁移是大 churn、
  部署目标 macOS 12 下 API 也受限，收益不成比例。
- **不拆 ViewerWindowController**（~550 行）：单窗口职责内聚，拆分只为行数好看。
- **保留手工 frame 布局**：窗口结构简单（两块主区 + 一排控件），Auto Layout 收益有限，
  且与原作手搓风格一致。
- **不缓存到磁盘**：缩略图/全图缓存都是进程内的，符合「零残留」的轻量定位；
  要持久缓存需要失效策略（mtime 校验等），当前场景不值得。
